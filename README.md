A hands-on IT infrastructure homelab that I built using a repurposed Acer Aspire ES 14, a used 5-port TP-Link 100 Mbps network switch, self-terminated Ethernet cables, and Windows Server 2019.

I built this project **about a month after completing my TESDA Computer Systems Servicing NC II**. The networking and basic computer systems concepts used in this project were skills I had already practiced during my TESDA training. Since I had the time and access to equipment and tools at home, I decided to continue practicing those skills and build a more complete physical Windows Server environment.

Rather than letting what I learned during TESDA fade after completing the training, I wanted to apply it again, troubleshoot problems on my own, and expand my knowledge by exploring Windows Server administration, Active Directory, DNS, DHCP, Group Policy, backup, print management, and networking.

This project became a way for me to **retain what I learned, gain more hands-on experience, and create something practical that I could include in my IT portfolio.**

---

## What I Learned

A lot of the fundamentals used in this project were things I had already encountered during my **TESDA CSS NC II training**. However, building the homelab at home gave me the opportunity to practice those skills independently and understand how the different technologies work together.

### Applying What I Learned From TESDA

During TESDA, I learned the fundamentals of computer systems servicing, networking, hardware, troubleshooting, and related IT concepts.

With this project, I was able to take those fundamentals and apply them in a larger hands-on environment.

Instead of only performing a task because it was part of a training activity, I had to figure things out myself, troubleshoot problems, and make decisions about how I wanted to build the lab.

This helped me become more confident working independently.

### Networking and Cable Termination

One of the biggest things I was able to practice again was physical networking.

I created my own Ethernet cables using RJ45 connectors and a crimping tool and followed the T568A wiring standard.

This was also the most difficult part of the project.

Getting the cable to properly pass the cable tester took me some time. Even when I thought the wires were correctly arranged, I would sometimes get a failed result. I had to check the wire order, make sure all eight wires reached the connector properly, re-crimp the connector, and test it again.

It was frustrating at first, but it taught me that even a simple physical networking task requires patience, accuracy, and troubleshooting.

Once I got the cables working correctly, the rest of the network setup went much more smoothly.

### Learning Beyond TESDA

While the fundamentals came from my TESDA training, this project also gave me the opportunity to go beyond what I had previously practiced.

I learned more about:

- Windows Server 2019
- Active Directory Domain Services
- Domain Controllers
- DNS in a Windows domain environment
- DHCP
- Organizational Units
- Security groups
- Group Policy
- Windows Server Backup
- Print Management
- Network discovery
- File and printer sharing
- Server troubleshooting

Building everything together helped me understand how these services are connected instead of viewing them as separate topics.

## Challenges I Faced

### Ethernet Cable Termination

The main difficulty I encountered was making my own Ethernet cables.

This was something I had already practiced during TESDA, but doing it independently at home was different. I had to troubleshoot the cable myself when it failed the tester instead of simply moving on to the next training activity.

It took several attempts before I consistently got a working cable.

The process taught me that having the knowledge is one thing, but being able to apply it accurately and troubleshoot your own mistakes is another.

After resolving the cable issue, the rest of the project was relatively smooth.

## A Lesson About Resources

One of the things I learned from this project is that **you do not necessarily need expensive equipment to continue learning IT.**

I used equipment that was already available to me, including an old Acer Aspire ES 14, a used 5-port network switch, basic networking tools, RJ45 connectors, and Ethernet cable.

The equipment is not enterprise-grade, but it was enough for me to build a functional environment where I could practice real IT infrastructure concepts.

Having limited resources actually encouraged me to be more creative with what I already had.

This project showed me that **the value of a homelab comes more from what you learn, build, troubleshoot, and document than from how expensive the equipment is.**
